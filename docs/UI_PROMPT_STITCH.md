# Stitch Prompt — DevPilot AI Premium AI-Native Developer Platform UI

## 1. ROLE & PROJECT CONTEXT

You are a **senior product designer, design-system architect, and frontend engineer with 20+ years of experience** building premium developer tools, SaaS platforms, AI products, and enterprise dashboards.

Generate the complete UI/UX for **DevPilot AI**, a sophisticated AI-powered developer-productivity platform that ingests a repository (GitHub URL or ZIP archive), analyzes it, and runs seven AI agents on it:

1. **Repository Analyzer** — detects languages/frameworks/dependencies, indexes files, writes project + architecture summaries.
2. **Code Review** — static security scan + optional LLM qualitative review; returns severity-graded issues and recommendations.
3. **Security Audit** — rule-based scanner; returns a security score, issues, and remediation alerts.
4. **Documentation** — generates README, API, architecture, install, contributing, changelog markdown.
5. **Testing** — generates unit / integration / e2e pytest scaffolds.
6. **QA Chat** — retrieval-augmented Q&A over the repository with source citations.
7. **Project Health** — computes documentation/testing/security/maintainability/complexity scores + an overall score + recommendations.

All agent results are **returned synchronously** by the backend; each run is triggered by an explicit user action (button) or an auto-flow after ingestion.

The UI must feel like a **premium AI-native developer operating system**, not a generic dashboard and absolutely not a template-generated admin panel.

The visual quality should feel comparable to the level of products such as **Linear, Vercel, Raycast, Cursor, GitHub Copilot, Arc, Stripe Dashboard, and modern AI developer platforms**, while maintaining a distinct **DevPilot AI identity**.

The interface should communicate:

* Intelligence
* Precision
* Speed
* Trust
* Developer-first tooling
* Technical sophistication
* AI-native interaction
* Professional enterprise quality

### IMPORTANT VISUAL DIRECTION

The interface should look like it was designed by a **senior product designer and implemented by an expert frontend engineer**, rather than automatically generated by an AI UI generator.

Avoid generic:

* SaaS dashboard templates
* Oversized cards
* Excessive rounded rectangles
* Random gradients
* Excessive glassmorphism
* Excessive purple backgrounds
* Giant hero text
* Stock illustrations
* Emoji
* Decorative elements without functional purpose
* Excessive shadows
* Excessive glowing elements

Instead, use **restrained futuristic/neon detailing**.

The neon effect should be subtle and purposeful:

* thin indigo/violet edge glows
* soft ambient radial light
* active navigation glow
* score-ring glow
* AI processing indicators
* hover illumination
* focused input borders
* selected tabs
* status indicators
* agent execution states

The product should feel **dark, intelligent, technical, refined and expensive**.

# 2. GLOBAL DESIGN SYSTEM

Apply this design system consistently across the entire application.

## 2.1 Aesthetic

Overall aesthetic:

**Minimal + Premium + AI-Native + Developer-Centric + Futuristic + Technical**

The foundation should be near-black with carefully layered surfaces.

Use:

* Near-black primary background
* Slightly lighter application surfaces
* Elevated cards
* Thin borders
* Subtle radial ambient lighting
* Extremely restrained neon accents
* Crisp typography
* Dense-but-breathable information hierarchy
* Precise spacing
* Monospace typography for technical information

The UI should feel **alive without becoming visually noisy**.

### Visual depth hierarchy

Use approximately:

```text
Level 0
#07070A / #0A0A0F
Application background

Level 1
#0D0D12
Primary surfaces

Level 2
#111118
Cards / panels

Level 3
#15151D
Elevated / interactive surfaces

Level 4
#1A1A24

```

Borders should generally use:

```text

rgba(255,255,255,0.08)
rgba(255,255,255,0.10)
```

Never use thick bright borders unless indicating an important active/focused state.

# 13. BACKEND API CONTRACT

Use the backend API contract exactly as provided.

Base URL:

```text
http://localhost:8000/api/v1
```

GET `/health`

→ `{status:"ok", app, version}`

GET `/repos`

→ `{status:"success", data:[{repository_id,name,source_url,status,summary,created_at}]}`

POST `/repos/upload`

→ FormData:

```text
source_type
source_value | archive
repository_name
```

Response:

```text
{status:"success", data:{repository_id,name}}
```

GET `/repos/{id}`

→

```text
{status:"success", data:{
repository_id,
name,
source_url,
root_path,
status,
summary,
architecture_summary
}}
```

POST `/repos/{id}/analyze`

Body:

```text
{analysis_scope:"full"}
```

Response:

# 14. MICRO-INTERACTION & POLISH REQUIREMENTS

This section is critical.

The generated frontend should have the level of interaction polish expected from a **senior frontend engineer**.

Implement:

### Hover

Interactive components should subtly respond to pointer movement.

Examples:

* cards lift 1px
* borders brighten
* icons shift 1–2px
* arrows move
* glow becomes slightly stronger

Never use exaggerated animations.

### Focus

Inputs and buttons:

```text
visible focus ring
+
subtle indigo glow
```

### Loading

Never freeze the UI.

Show meaningful progress where possible.

### Success

Use:

* check icon
* toast
* subtle status transition

### Error

Clearly explain:

```text
what happened
+
what the user can do
```

### Tooltips

Use tooltips for unfamiliar icon-only controls.

### Skeletons

Skeleton dimensions should match final content dimensions.

Avoid generic full-page skeleton blocks.
